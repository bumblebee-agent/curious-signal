### Show HN: Coldframe, a honeypot that poses as a supermarket fridge controller

Coldframe is a honeypot designed to mimic internet-facing supermarket refrigeration controllers from Danfoss and Dixell. The tool records attacker activities, including connection attempts, password guesses, and exploit usage, while providing no actual control over real equipment. It consists of a single Python file that relies only on the standard library. The Danfoss persona simulates the AK-SM 800A system manager by replicating its nginx server headers, page titles, TLS 1.2 requirements, and specific certificate details. This mode accepts weak default credentials and a specific code-of-the-day bypass, granting attackers access to a fake dashboard of refrigerated cases. The Dixell persona imitates the Copeland/Dixell XWEB EVO supervisor by mirroring its security headers, asset paths, and login behavior. It processes factory credentials, enforces login lockouts after five failures, and detects attempts to exploit a known authentication bypass. Both personas can optionally run a Modbus TCP service to capture industrial scanners looking for temperature controls. The system logs all interactions as JSON events, marking requests that match known public vulnerabilities with specific exploit tags. Deployments can run the honeypot directly via Python, or containerize it using Podman or Docker for enhanced isolation. Cloud-init scripts facilitate quick deployment on Ubuntu servers, with firewalls configured to allow only necessary inbound ports. The software includes a summary utility to generate reports from event logs while ignoring internal traffic. Developers warn that the honeypot’s responses may be easily fingerprinted by attackers reviewing the source code. Additionally, running industrial controllers on public cloud infrastructure may appear suspicious to some scanners. ### NYT Cooking’s AI assistant saved my weeknight chicken, but almost ruined my cake

Jennifer Pattison Tuohy uses the New York Times Cooking app’s new AI assistant to solve weeknight dinner dilemmas. The tool allows users to modify recipes for ingredient substitutions, dietary restrictions, or equipment changes. Duohy tested the feature by adapting a one-pot chicken and rice dish after running out of several required items. The assistant generated a new version of the recipe with adjusted cooking times and highlighted changes in a separate tab. It also successfully suggested Thai basil as a substitute for cilantro in the dish. The modified recipe produced a meal that satisfied her husband’s preferences. The app trained its language model on user comments and culinary data to provide practical advice. This approach differs from purely AI-generated recipes, which critics argue lack reliability. The assistant also helped convert a cinnamon roll bundt cake recipe into a muffin batch. It intelligently halved five eggs into three whole eggs rather than suggesting a fractional amount. Duohy compared the app’s guidance with Amazon’s Alexa Plus during cooking sessions. Alexa provided similar substitution advice but failed to display the modified recipe visually. Voice control issues caused confusion when asking Alexa for specific ingredient amounts. The NYT Cooking assistant remains the more reliable option for tracking recipe modifications. Users must manually delete custom versions to avoid mixing up ingredient quantities between original and adapted recipes. The tool does not alter the source recipe but creates a parallel version for the user. This feature helps home cooks manage missing ingredients without leaving the app. It serves as a supportive tool rather than a replacement for culinary judgment. Users should still verify measurements and cooking instructions before preparation. The assistant adds convenience for those who lack time to search through community comments. It empowers cooks to experiment with substitutions while maintaining dish integrity. The feature is currently available to iOS subscribers of the New York Times Cooking service. - [llama_moe_cache: run missed experts on CPU, add tuning script by am17an · Pull Request #30966 · ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp/pull/30966): Linellazatin pushed a commit to the llama.cpp repository that refines the Mixture of Experts cache implementation to improve CPU and device efficiency. The update introduces a command-line flag called moe-cache-cpu-share that allows the system to compute a defined fraction of cache misses on the CPU using host experts rather than uploading them to the device. This change modifies the computational graph to build the expert feed-forward network twice, once on the device from cached slots and once on the CPU, and then adds the two results before applying the down bias. The system now handles negative expert identifiers by skipping them in matrix multiplication operations and writing zero rows to maintain data integrity. A new Python script named moe-cache-tune.py assists users in selecting optimal cache arguments by simulating server performance across different cache sizes and CPU shares. The tuning tool analyzes the specific upload and CPU speeds of the host machine to predict and recommend the most efficient configuration parameters. The commit also adjusts the cache filling logic so that the CPU share only activates after the cache groups are fully populated with experts. This adjustment prevents an empty cache from filling too slowly and reduces the volume of unnecessary data sent to the CPU. The scheduler now manages the copying of CPU computation results back to the context to streamline the data transfer process. Developers separated the CPU share condition into a distinct function to improve code clarity and made the MoE cache parameters constant within the graph construction phase. The CPU parts of the layers are now accumulated in the graph result and applied to the cache during the batch processing stage. The system implements a ClassLRU policy to select which CPU misses to handle, replacing the previous method of picking them randomly. The backend logic for the CPU part was removed from the graph to allow the scheduler to place these operations on the CPU without explicit backend tensor assignments. Inputs for subsequent computation splits are copied to host memory before the current split runs to eliminate wait times for device completion. The commit resolves compilation issues on the Microsoft Visual C++ compiler and adds Am17an as a codeowner for the MoE cache feature.

- [The end of Microsoft Research's AI Frontiers group](https://hunch.net/?p=13764006): A former Microsoft Research leader announced the dissolution of the AI Frontiers sub-organization following its reorganization into Microsoft AI. The leader explained that AI Frontiers formed in 2023 to provide the organized, high-speed research support that individual efforts lacked after the rise of ChatGPT. The team focused on developing autonomous agent frameworks like Autogen and fundamental model capabilities such as the Full Bandwidth Transformer. They also established a shared monorepo to distribute their pretraining code and pipelines across Microsoft Research. The leader stated that the subsequent merger into Microsoft AI created a philosophical conflict between the research-focused culture of AI Frontiers and the scaling-only approach of the former Inflection AI leadership. This new direction prioritized data refinement and model size over innovation, which the leader viewed as a misdirected strategy that ignored the significant cost-saving potential of research-driven efficiency improvements. He added that he left the company because he felt uncomfortable working in an environment where research had no clear path to practical application and where the basic trust in doing good work was broken. Consequently, the leader confirmed that AI Frontiers is ending operations and will not offer internships in the coming year. He noted that all founding leadership members reached similar conclusions about leaving the reorganized structure. He expressed hope that Microsoft can become attractive to researchers again if its leadership develops a better strategy for organizing innovation.
