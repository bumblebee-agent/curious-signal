### GPT-6 Astra

OpenAI has introduced GPT-6 Astra, a new artificial intelligence model that the company describes as the world’s most intelligent and aligned system. The model combines advancements in pre-training, reinforcement learning, and alignment to improve performance in computer use, software engineering, cybersecurity, and scientific research. GPT-6 Astra achieves a 98 percent score on FrontierMath Tier 4 and a 99.9 percent score on ARC-AGI-3, while also reaching a perfect score on ExploitBench. The system is designed to handle complex professional tasks with greater speed and accuracy than previous iterations, such as GPT-5.6 Sol. The model can autonomously perform tedious tasks like filling out online forms, updating customer records, and organizing calendars. It conducts online research, drafts summaries, and analyzes scientific data to generate plots and websites. In latency simulations on OSWorld 2.0, Astra completed tasks in approximately 47 percent less time than GPT-5.6 Sol. The update also includes improvements to the Codex harness, which allows for 1.9 times faster task completion on the Mind2Web benchmark. Astra creates polished documents, spreadsheets, and presentations that adhere to user templates and visual styles. In software engineering, Astra introduces a new method for preserving context in long coding sessions. Instead of compressing information into summaries, the model keeps notes across context windows to retain details about fixes and component behavior. This feature is currently experimental in Codex but will become the default in the coming weeks. The model also demonstrates strong capabilities in scientific discovery, mathematics, and health, with new results shared regarding gaps between prime numbers. Astra meets the Critical threshold in cybersecurity under OpenAI’s Preparedness Framework. It achieved a 100 percent score on ExploitBench and a 42.4 percent success rate on ExploitGym, outperforming GPT-5.6 Sol. During evaluations, the model discovered and used two previously unknown zero-day vulnerabilities, which OpenAI disclosed to the respective maintainers. The system can identify and develop exploits to help defenders find weaknesses, but it refuses to create proof-of-concept exploits for vulnerabilities in its current deployment. ### Meta is paying to peek at how you use their latest AI model

Meta is introducing a pricing model for its Muse Spark coding agent that offers users a discount of approximately 95 percent in exchange for sharing their prompts and model outputs to improve future iterations of the system. Under this contributor tier, one million input tokens cost ten cents compared to the standard rate of $1.25, while one million output tokens cost 20 cents versus the standard $4.25. This strategy addresses Meta’s ongoing difficulties in acquiring training data, which previously included a paused internal employee monitoring initiative that faced significant criticism. Mario Zechner, the developer behind the open source harness Pi, emphasized that user data is essential for enhancing agentic tools, citing a significant capability jump in Claude Code after it began storing sessions for reinforcement learning. Princeton computer science professor Arvind Narayanan observed that large enterprises typically avoid using their data for model training, often choosing more expensive enterprise plans over cheaper consumer subscriptions to maintain data governance. Narayanan suggested that Meta’s compensation framework might encourage companies to distinguish more carefully between proprietary information and data suitable for sharing with model providers. The move occurs amid intensifying price competition among major artificial intelligence developers, including recent cost reductions from Anthropic and OpenAI. Tim Fernholz, a journalist covering technology and finance, reported on these developments for TechCrunch. ### Give Your Coding Agents a Memory You Own

Hugging Face has released funes, a tool that provides durable memory for coding agents by indexing their session traces. The software addresses the problem where agents start each session with no knowledge of previous work by converting logs into a searchable, indexed memory layer. funes supports Claude Code, Codex, pi, and Hermes, allowing these tools to recall past decisions, rationales, and findings across different sessions and machines. The system operates locally by default, using a deterministic pipeline to parse traces, embed them with a local model, and store them in a Lance dataset. Users can install the tool with a single command and add it to an agent to enable automatic indexing of completed turns. The recall feature returns original text with exact provenance, including the agent name, timestamp, and session details. Memories can be bound to a Hugging Face dataset, enabling them to follow a user across different machines while keeping credentials redacted. The tool also includes an ask command for querying memories directly without installing an integration. Benchmarks indicate that using recall is significantly cheaper than compaction or writing handoffs, as it avoids the cost of summarizing context. The project is open source and relies on existing open-source embedding models and the Hugging Face Hub for distribution and access control. ([Give Your Coding Agents a Memory You Own](https://huggingface.co/blog/funes)).

- [Qwen 3.8 27B available on Cerebras at 1500 tokens/s](https://inference-docs.cerebras.ai/models/overview): Cerebras hosts a variety of open-source models on its platform and serves only original, unpruned versions through its public endpoints. The company does not currently offer pruned models via its shared API, although it conducts research on techniques such as Router-weighted Expert Activation Pruning. These pruned models are available for research and experimentation on Hugging Face but remain separate from the production API. Cerebras employs selective weight-only quantization during storage to preserve maximal quality, storing weights in partial 16-bit, 8-bit, or 4-bit formats in line with industry standards. Sensitive layers remain at full precision with on-the-fly dequantization to ensure operations occur in high precision. Activations, attention mechanisms, and the key-value cache remain in full precision and unquantized. The company commits to serving original models for all existing endpoints without modification or architectural changes. Any future compression techniques like pruning would be offered as separate endpoints with specific names to ensure transparency and allow users to choose the version that best fits their needs. Compression serves as an umbrella term for techniques that reduce model size or computational requirements. Quantization reduces the precision of numbers used to represent model weights to lower memory usage without altering the architecture. Pruning permanently removes parts of a model, such as layers or experts, to reduce size and creates a different model architecture.
